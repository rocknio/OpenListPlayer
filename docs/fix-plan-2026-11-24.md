# OpenListPlayer（云序）四批次修复实施计划

- **关联审查报告**：`docs/code-review-2026-11-24.md`
- **制定日期**：2026-11-24
- **实施原则**：
  1. 严格遵守 `AGENTS.md` 规范：保持分层依赖 `ui → player → data → core`（`core/` 零 Flutter 依赖）、文件头 `/// 职责说明` + `library;`、项目内相对路径 import、不跑整仓 `dart format`（手工跟随所在文件缩进与风格）、不改动钉死的依赖与平台规避策略。
  2. 数据库 schema 变更必须递增 `schemaVersion`，在 `migration.onUpgrade` 添加分支并执行 `dart run build_runner build --delete-conflicting-outputs` 同步更新 `app_database.g.dart`。
  3. 每一批次完成后运行 `flutter analyze --no-pub` 与 `flutter test` 验证零新增 error/warning 且测试全绿；全部四批次完成后，通过独立 subagent 执行最终验收审查。

## 第一批：网络与平台阻断项（H-1, H-2, H-3, H-4 + M-6 URL/403 降级 + 单测）

### 目标与修改文件
1. **`lib/core/openlist_client.dart`**
   - **修复 H-1（请求头方括号）**：解析 `body['header']` 时兼容 Go `http.Header`（`Map<String, List<dynamic>>`）与单值字符串；`Cookie` 多值用 `'; '` 连接，其余头用 `', '` 连接，忽略空列表与 `null`。
   - **修复 H-2（代理路径编码）**：`raw_url` 为空拼接 `/d/...` 时，按路径段 `path.split('/').map(Uri.encodeComponent).join('/')` 编码（安全处理 `#`、`?`、`%`、`&`、`+`、空格与中文），`sign` 使用 `Uri.encodeQueryComponent(sign)`。
   - **完善 M-6 网络健壮性**：`_normalizeBase` 循环去除全部末尾 `/`；`listDir(refresh: true)` 同时捕获业务层 `OpenListApiException(statusCode == 403)` 与 HTTP 层 `DioException(response?.statusCode == 403)` 静默降级为 `refresh: false`（不再强耦合英文 `'refresh'` 字样）；新增 `void close() => _dio.close()` 供 Riverpod 销毁连接池。
2. **`lib/core/models.dart` & `lib/data/settings_service.dart` & `lib/providers.dart`**
   - 为 `SiteConfig` 实现 `operator ==` 与 `hashCode`，并提供静态校验/归一化辅助函数（如 `SiteConfig.tryNormalizeUrl`：要求 `http` / `https` scheme 且 `host` 非空，去除末尾 `/`）。
   - `SettingsService.saveSite` 与 `load` 防御非法空 host URL；`apiProvider` 注册 `ref.onDispose(client.close)`。
3. **`ios/Runner/Info.plist`**
   - **修复 H-3（iOS ATS 冲突）**：移除会导致 iOS 10+ 忽略 `NSAllowsArbitraryLoads` 的 `NSAllowsLocalNetworking` 键，保留 `NSAllowsArbitraryLoads = true`；补充 `NSLocalNetworkUsageDescription` 中文权限说明。
4. **`ios/Runner/AppDelegate.swift`**
   - **修复 H-4（`UIScene` 下 MethodChannel 未注册）**：将 `olp/device` MethodChannel 注册移至 `didInitializeImplicitFlutterEngine(_ engineBridge:)`，使用 `engineBridge.applicationRegistrar.messenger()`。
5. **新增测试 `test/openlist_client_test.dart`**
   - 覆盖 Go `http.Header` 数组解析（常规头与 `Cookie`）、`/d` 代理地址对 `#` / `?` / `%` / 中文 / `sign` 特殊字符编码、guest `403`（业务码 403 与 HTTP 403）下拉刷新自动静默降级、`SiteConfig` 值相等与 URL 归一化。

## 第二批：播放内核与通知栏（H-5, M-1, M-2, M-3, M-4 + L-1 部分调试清理）

### 目标与修改文件
1. **`lib/player/playback_controller.dart`**
   - **修复 H-5（切歌流事件污染、重试串歌、进度异步竞态）**：
     - 引入 `_loadedSerial`（仅在 `_player.open` 即将发出/完成时对齐 `_openSerial`）与可取消的 `Timer? _retryTimer`；
     - `replaceQueue` / `jumpTo` / `next` / `previous` 先停 `_progressTimer`、捕获旧曲目快照并 `await _recordProgressSnapshot(...)`（不写旧会话），再切换队列与 `_sourcePlaylistId`，随后进入 `_openCurrent`；
     - `_openCurrent` 开头递增 `_openSerial`、取消 `_retryTimer` 与 `_progressTimer`、重置 `_restoredPosition = null`，并先调用 `await _player.pause()` 冻结旧媒体流，避免等待 `getFileLink` 期间旧曲目 `position` / `completed` / `error` 污染新曲目；
     - 在 `_positionSub`、`_durationSub`、`_playingSub`、`_bufferingSub`、`_completedSub`、`_errorSub` 中校验 `_loadedSerial == _openSerial`；
     - `_onPlayerError` 使用可取消 `_retryTimer` 替代 `Future.delayed(800ms)`，回调触发时严格校验 `!_disposed && serial == _openSerial && status != PlaybackStatus.idle`，并用去重标记避免同一次 `open` 抛错与 `stream.error` 双重触发。
   - **修复 M-1（轨道同步与关闭字幕记忆）**：
     - 在 `_bindStreams()` 绑定 `_trackSub = _player.stream.track.listen(...)` 同步 `currentAudio` / `currentSubtitle` 并 `_notify()`；
     - `_maybeApplyTrackPrefs` 遇到 `prefs.subtitleTrack == ''` 时显式调用 `_player.setSubtitleTrack(SubtitleTrack.no())` 压制内置默认字幕；
     - `addExternalSubtitle` 增加 `serial == _openSerial` 校验。
   - **修复 M-3（播单进度重播误删）**：
     - `_openCurrent` 读取播单进度遇到 `p.finished || ProgressRules.isFinished(...)` 时，**不再提前删除 `playlistProgresses` 行**，仅令 `start = null` 从头播；等实际开播并产生 `<95%` 有效进度时由 `upsertPlaylistProgress(..., finished: false)` 自然覆盖，避免断网或点错退出丢失“已看完”标记；
     - `_writePlaylist` 外键失败时若播单已被删除，自动将 `_sourcePlaylistId = null` 回退到全局进度。
   - **修复 M-4（会话恢复、倍速与切换站点边界）**：
     - `seek()` 同步更新会话（含已知 `duration`）并在末尾调用 `_notify()` 通知锁屏刷新位置；
     - `resumeSession()` 支持读取会话持久化的 `durationMs`（解决首播未满 5s 拖进度退出后 `durMs == 0` 丢失断点问题），若关联播单已不存在则自动回退 `_sourcePlaylistId = null` 读全局进度；
     - `togglePlay()` 在 `status == PlaybackStatus.idle && current != null` 时调用 `resumeSession()`；
     - 新增临时倍速字段 `effectiveSpeed`（供通知栏按真实倍速推算进度），并提供 `resetForSiteChange()` 在切换/清空站点时安全停播清理；
     - 顺带确保 `_applyBufferProfile` 首次模拟器检测可被 `_openCurrent` 等待完成，并清理 `playback_controller.dart` 中的 3 处 `TODO(debug)` 及敏感直链/请求头日志脱敏（关联 L-1）。
2. **`lib/player/audio_handler.dart` & `lib/providers.dart`**
   - **修复 M-2（通知栏时长、进度、耳机唤醒与前台服务停止）**：
     - 保存所有 `StreamSubscription` 并提供 `dispose()` 挂入 `audioHandlerProvider` 的 `ref.onDispose`；
     - 监听 `player.stream.duration`，当曲目真实时长解析就绪时动态更新 `mediaItem` 的 `duration`（及可用 `artUri`），切歌 `opening` 瞬间不再误取上一首曲目的旧 `duration`；
     - `_pushPlaybackState` 使用 `effectiveSpeed`；
     - `play()` 在 `idle` 态转调 `_c.resumeSession()`、在 `error` 态转调 `_c.retryNow()`；
     - `stop()` 调用 `_c.stop()` 后执行 `await super.stop()` 确保 Android 前台服务正常释放；
     - `AppSettingsNotifier.setSite` 在站点 URL 变化或清空时调用 `playback.onSiteChanged()` 停播旧队列。
